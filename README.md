# 林记烘焙 · A Little Bakery Story

移动端竖屏经营游戏。36 个月、180 个经营日，从一家社区老店做到连锁品牌。
按 `story/游戏设计方案 V5.md` 的架构实现，**剧情直接读 `v5_0.md`**。

## 怎么跑

### 只是想玩

双击项目根目录的 **`双击开始游戏.bat`**，或者直接双击 `dist/林记烘焙.html`。

存档在浏览器 localStorage 里，自动保存。

### 想改东西

```bash
npm install      # 第一次
npm run dev      # http://127.0.0.1:5180
```

### 重新生成可双击的版本

```bash
npm run build
```

产出三份内容相同的单文件 HTML：`dist/index.html`、`dist/play.html`、`dist/林记烘焙.html`。
构建末尾会自动跑 `tools/make-standalone.mjs` 把 JS/CSS 内联进去，并带语法自检。

## 剧情怎么演

剧情是整屏的 AVG 演出，不是弹窗：

- **背景**：按 `【场景：…】` 自动切（店内 / 后厨 / 街道 / 家 / 市集 / 学校 / 河边 / 夜…），带淡入和回忆滤镜
- **立绘**：谁说话谁亮，没说话的压暗后退；同时最多站三个人
- **CG**：`**【CG：festival】**` 起、`**【CG 结束】**` 止，换场景也会自动收起
- **对话框**：底部固定，名字旁带小头像，正文有打字机效果；点屏幕推进，点一下先出完整句
- **顶上两个按钮**：「自动」按 1.4 秒一句往下播；「跳过」快进到下一个选项或结尾

**图片全部按文件名自动加载**，没有图就用暖色氛围底兜底，不会破图也不报错：

| 文件 | 放在 | 说明 |
|---|---|---|
| `bg-shop.webp` `bg-kitchen.webp` … | `public/art/` | 场景背景，11 个 key 见 `src/vn.js` |
| `cg-festival.webp` `cg-finale.webp` … | `public/art/` | 整屏 CG，key 由文案里的 `【CG：…】` 指定 |
| `ln-sprite.webp` `xy-sprite.webp` … | `public/art/` | 立绘（透明底），缺图就不站人 |
| `cake-<id>.webp` | `public/art/` | 12 款蛋糕的产品图，缺图退回手绘 SVG |

要哪些图、每张怎么描述，写在 **`素材需求.md`** 里，可以直接粘给绘图工具。

## 剧情怎么写

**唯一数据源是根目录的 `v5_0.md`。改它，刷新页面就生效，不用碰代码。**

解析器认识这些写法：

```markdown
## 第一章：接手林记（第1—6个月）      ← 章节，会显示在弹层副标题

### M5｜第一笔大型订单                  ← 一个事件；M5 = 第 5 个月触发

**【事件ID：EVT_M05_MAIN｜触发月份：M5第2个经营日】**
**【状态变更：解锁「定制订单系统」】**   ← 这类标记只作文档用，游戏不读

林念：这笔大单由你独立接洽。            ← 台词，行首是角色名
旁白（苏晴视角）：其实早在几年前……      ← 旁白，括号里是视角
**【场景：栖云镇 · 林记烘焙】**          ← 场景分隔线
**【插入回忆片段 8.1：高一】**           ← 同上，用作闪回分隔

> **【玩家选择节点 11.1（M5）：订单方案】**
> * **选项A：采用传统奶油装饰**（`traditionScore + 5`）
> * **选项B：尝试新的装饰方式**（`innovationScore + 5`）
> * **选项C：先询问顾客具体喜好**（`communityScore + 5`，顾客忠诚度增加）

**【分支A：选择「采用传统奶油装饰」】**   ← 选项对应的后续，按 A/B/C 对号入座
林念：阿姨，林记最拿手的就是……
**【主线汇合】**                          ← 分支结束后所有路线共用的内容
```

效果写法：`traditionScore / innovationScore / efficiencyScore / communityScore +N`、
`小雨信赖度 +N`、`专业能力 +N`、`顾客忠诚度增加`。程序会把它们变成按钮下方的小字。

条件段落（不满足就不播，满足才播）：

```markdown
**【若许知遥信赖度 ≥ 60，额外触发个人交心剧情】**：  ← 单条件段落
许知遥：念念，其实我心里一直有个目标……

* **【高养成解锁分支：小雨信赖度 ≥ 70 且已完成M11创意研发剧情】**
  小雨捧着三盘标好记号的栗子泥小样……
* **【普通保底分支：未满足高养成条件】**
  林念带领小雨耗费数个经营日……
```

阶段结算写在每月 6 的倍数后面：

```markdown
### 【M6月末：第一阶段目标结算】
**【检查条件（三项完成两项即可进入第二章）：……】**
#### ▶ 分支一：阶段达标（进入第二章）
林暖：短短半年，你把老顾客照顾得妥妥帖帖……
#### ▶ 分支二：阶段未达标 → 触发短线结局 10.1《街角的灯》
**【事件ID：EVT_SHORT_END_01｜触发条件：M6结算完成目标数 < 2】**
夏夜的晚风吹过栖云镇的街角……
```

其他成块的内容也各就各位：

- `附篇一` 的四段 → **经营风格专属剧情**，某项 ≥60 且领先 15 分时自动触发
- `附篇二` 的五段 → 经营页「和苏晴聊聊」随机播一段
- `第十三章 13.1–13.6` → 六种最终结局
- `13.7` → 结局弹层里的「他们的后来」，按信赖度/专业能力挑档
- `14.1` 表格 → 图鉴里的风味描述与配方提示

写错格式不会崩：控制台会打印 `[剧情] 已加载 N 个事件`，解析不到的段落直接跳过。

## 核心循环

每个经营日四步：

1. **厨房** — 排今天的产量。每款产品有售价档位（亲民 / 标准 / 精品）和预计销量。
2. **店铺** — 接今天的订单，开门营业，结算当天销售。
3. **打烊** — 处理没卖完的（打折 / 留给伙伴 / 社区分享 / 报损），然后进入下一天。

每天恢复 **8 点行动力**（装修可升到 10）和 **70 点体力**（上限 100）。
每月 5 个经营日，第 5 天打烊后做**月末结算**：扣固定成本、出经营报告。

**产能** = 体力 + 妈妈 60 点 + 每位伙伴 40 点。超出免费产能的部分才扣你的体力。

每 6 个月做一次**阶段结算**：完成规定数量的目标才能进入下一章，否则本局直接进入对应的短篇结局。
第 36 个月进入最终结局（社区老店 / 传统老字号 / 创意品牌 / 区域连锁 / 全国连锁），
M32 接受收购邀约则走《转让》。

## 已实现

- 5 个页签：店铺 / 厨房 / 伙伴 / 经营 / 图鉴
- 180 个经营日，行动力 + 体力双资源
- 生产排产、定价三档、自然客流、每日订单、剩货处理
- 12 款产品按月份解锁，各自独立熟练度
- 4 位具名伙伴，按剧情月份加入，各自有信赖度与专业能力
- 52 段剧情全部接通：主线 36 个月 + 5 个短线结局 + 4 段风格剧情 + 6 个最终结局
- 10 处分叉选择，效果落到风格分 / 信赖 / 专业能力
- M27 的伙伴专属协助按信赖度自动分流（高养成 / 保底）
- 结局弹层带「他们的后来」，按养成挑档
- 图鉴里的风味描述与配方提示取自文案 14.1
- 12 款蛋糕已接入产品实拍图，厨房排产与图鉴都能看到
- 七件设备（烤箱/搅拌机/冷藏柜/展示柜/包装台/仓库/收银），各三级，实装效果
- 月末经营报告、本地存档

## 尚未实现

- **顾客系统**：只有需求量模型，没有具名常客档案
- **装饰系统**：只有店铺等级，没有单独购买摆件
- **订单类型**：只有普通/定制/线上/节日四种计数，没有企业团购与纪念日
- **每日流程细化**：没有「查看今日情况」「顾客自动进店」的分步演出
- **二周目与云存档**：未实现
- 属性面板只显示口碑/知名度/忠诚，`brandInfluence`、`customerLoyalty` 等未在界面单独展开
